# AI Agent Guidelines – Catalog E2E Test

This document provides essential information for AI agents (Claude, Copilot, Cursor, etc.) working on the Catalog E2E Test project.

## 🛠 Tech Stack

- **Language:** TypeScript (strict); build/orchestration scripts are plain Node ESM (`scripts/*.mjs`)
- **Test runner:** Playwright (`@playwright/test`), Chromium only
- **HTTP:** axios (test data setup/cleanup against the BE REST API)
- **Application under test:** Catalog BE + FE run in Docker (PostgreSQL, `catalog-be`, `catalog-fe` on nginx)
- **Prerequisites:** Node.js (latest LTS), Docker, sibling checkouts `../catalog-be` and `../catalog-fe`; Catalog FE reachable at `FE_BASE_URL`

## 🚀 Key Commands

- **Install:** `npm install` then `npx playwright install chromium`
- **Prerequisite for FE build:** `.env.local` with `HASH_SALT`
- **Run tests:** `npm run test` (UI mode: `npm run test:ui`) – application must be running
- **Full cycle (build, start stack, test, tear down):** `npm run test:e2e`
- **Docker stack:** `npm run build:be`, `npm run build:fe`, `npm run build:docker`, `npm run docker:up`, `npm run wait`, `npm run docker:down`
- **Lint:** `npm run lint` / **Type check:** `npm run type-check`

## ⚙️ Configuration

- `.env` (committed): `FE_BASE_URL` (fallback `http://localhost:8010`), `BE_BASE_URL` (fallback `http://localhost:8110`), `CATALOG_USERNAME`, `CATALOG_PASSWORD`,
  `ITEMS_PER_PAGE` (items per page of FE lists; also used by tests for paging).
- `.env.local` (git-ignored, secrets, created manually, overrides `.env`): `HASH_SALT`. `CATALOG_*`, `BE_BASE_URL`, `ITEMS_PER_PAGE` and `HASH_SALT` are required by `scripts/build-fe.mjs`;
  no config values are hardcoded in scripts.
- Never put secrets (e.g. `HASH_SALT`) in `.env` or commit `.env.local`.
- Config is loaded by `scripts/lib/env.mjs` (scripts) and `playwright.config.ts` (tests); real environment variables win over both files.
- Docker stack ports: FE `8010`, BE `8110`. BE credentials default to `catalog`/`catalog`; the FE `config.json` is generated by `scripts/build-fe.mjs` from `.env` and `.env.local`.

## 📝 Coding Standards

- Strict TypeScript, no `any` without justification.
- **Markdown:** lines are at most 200 characters; wrap longer paragraphs and bullets at that width and indent continuation lines of a list item.
- One page object per FE route/page in `pages/` (no base classes; a `pages/<resource>/` subfolder only when a resource has more than one page). A form shared by add and edit routes is one page object
  (e.g. `GenreFormPage`).
- One spec file per FE route in `tests/<resource>/` (e.g. `list.spec.ts`, `add.spec.ts`, `edit.spec.ts`), each covering everything the route offers: rendering, auth redirect, BE persistence, prefill
  from BE, validation, paging, filtering, navigation.
- Specs import `test`/`expect` from `fixtures/test`; logged-in tests use the `authedPage` fixture (BE API login, session seeded into `sessionStorage`), the login/registration UI is tested with plain
  `page`.
- Test data is created through the BE API (`api/`, factories in `utils/testData.ts`) and removed in `try/finally`. Accounts cannot be deleted via the API: never assert absolute account counts.
- BE error responses (e.g. the result error modal, empty catalog) are simulated with `mockResponse` from `utils/mock.ts` (`page.route`) instead of real data.
- Usernames must stay short (BE audit columns are `VARCHAR(36)`): use `credentials()`, not `uniqueName()`.
- Do not commit generated `docker/fe/dist/`.
- Run `npm run lint` and `npm run type-check` before considering a change done.
